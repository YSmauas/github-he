# איפיון — גרסאות 0.0.x (scope של 0.0.1, מעודכן; הגרסה הנוכחית 0.0.2)

> סקריפט Tampermonkey שמתרגם את הממשק של `github.com` לעברית.
> מאגר: `YSmauas/github-he`.

## שינויים מהטיוטה הראשונה

1. **שליחה למפתח:** במקום ייצוא קובץ ושליחה ידנית — כפתור "📤 שליחה למפתח" שיוצר Issue במאגר דרך ה-session של המשתמש (סעיף 6.9).
2. **עדכון אוטומטי של המילון** מהמאגר, בנפרד מעדכון הקוד (סעיף 3.6).
3. **ללא רשת בזמן ריצה** — בוטל. הרשת מותרת לשני יעדים בלבד, וכל אחד עם הגנות (סעיפים 3.6 ו-6.9).
4. הוחלט על שם המאגר `github-he` ועל הבעלים `YSmauas`.

> מה שמסומן **[לא נבדק מול האתר]** נבדק רק מול עמוד דוגמה בדפדפן; ההתנהגות מול github.com האמיתי עדיין לא נוסתה.

## 0. מטרות ולא-מטרות

### מטרות של 0.0.1
1. להחליף טקסט ממשק באנגלית בעברית ב-`github.com`, בדפים המרכזיים (סעיף 11).
2. מילון חיצוני לקוד: אפשר לעדכן תרגומים בלי לגעת בלוגיקה, ובלי להוציא גרסת קוד חדשה.
3. טקסט עברי בכיוון RTL, **בלי** להפוך את פריסת האתר ובלי יישור לימין.
4. **מצב איסוף** שמגלה מחרוזות שעוד לא תורגמו, בצורה בטוחה לפרטיות.
5. **שליחה למפתח** בלחיצת כפתור, אחרי אישור המשתמש.
6. **עדכון אוטומטי** של המילון מהמאגר.
7. מונחי GitHub נשארים באנגלית (commit, pull request, issue, branch, repository, fork וכו').
8. עובד ברשת של נטפרי: גם בלי גישה למאגר, הסקריפט עובד עם המילון המובנה.

### לא-מטרות של 0.0.1
- תרגום תוכן משתמשים (issues, הערות, README, קוד, הודעות commit).
- תרגום אוטומטי/מכונה בתוך הסקריפט.
- שפות נוספות (הארכיטקטורה תאפשר, לא ממומש).
- GitHub Enterprise Server, `gist.github.com`, `docs.github.com`, GitHub Pages.
- ממשק גרפי מתקדם לביקורת מחרוזות (יהיה ב-0.1).
- תרגום משפטים שמורכבים מכמה אלמנטים (סעיף 2.5).
- שליחה אוטומטית ברקע ללא אישור המשתמש — **בכוונה**: ה-Issue ציבורי ומשויך לחשבון המשתמש.

## 2. מנגנון ההחלפה — איך יודעים איזה משפט מתורגם לאיזה

### 2.1 העיקרון: המחרוזת האנגלית היא המפתח
כמו ב-gettext (`msgid`): אין מזהים. המילון הוא מיפוי **טקסט אנגלי מדויק ← טקסט עברי**.

```json
{
  "Pull requests": "Pull requests",
  "Merge pull request": "ביצוע merge ל-pull request",
  "Sign in": "כניסה",
  "{n} commits": "{n} commits",
  "1 commit": "commit אחד"
}
```

### 2.2 נרמול לפני חיפוש
לכל צומת טקסט (`Text node`):
1. שומרים את הרווחים בתחילת הצומת ובסופו (GitHub מוסיף שורות חדשות והזחות).
2. מחשבים מפתח: `key = text.replace(/\s+/g, ' ').trim()`.
3. מחליפים NBSP ותווי רוחב-אפס ברווח רגיל לצורך החיפוש בלבד.
4. אחרי החלפה: `nodeValue = leadingWS + hebrew + trailingWS`.

### 2.3 סדר החיפוש (עדיפות יורדת)
1. **התאמה מדויקת מוגבלת-הקשר** — רשומה עם `scope` (ביטוי רגולרי על נתיב ה-URL או סלקטור). לפתרון דו-משמעות ("Open" כפועל מול "Open" כמצב).
2. **התאמה מדויקת גלובלית** — `Map.get(key)`, O(1).
3. **תבנית** — מפתחות עם `{n}` / `{1}` / `{2}`:
   - `{n}` = מספר: `(\d[\d,.]*[kKmM]?)`
   - `{1}`,`{2}`… = טקסט חופשי קצר: `(.+?)`
   - מקומפל פעם אחת ל-RegExp מעוגן (`^…$`), מאונדקס לפי המילה הארוכה ביותר שבו כדי שלא נריץ את כל התבניות על כל צומת.
   - בעברית ממלאים: `"{n} commits"` → `"{n} commits"`, `"Merged {1} into {2}"` → `"בוצע merge של {1} אל {2}"`.
4. לא נמצא → מעבירים ל-Collector (אם מופעל) ולא נוגעים בטקסט.

**החלפה רק על התאמה של כל הצומת.** לא מחליפים חלקי מחרוזות ולא מילה-במילה. זה מונע שיבוש של טקסטים שלא מכירים.

### 2.4 יחיד / רבים
שתי רשומות נפרדות, והמדויקת גוברת על התבנית:
```
"1 commit"   → "commit אחד"
"{n} commits"→ "{n} commits"
```

### 2.5 משפטים שמורכבים מכמה אלמנטים (מחוץ ל-0.0.1)
דוגמה: `<a>octocat</a> opened this issue 3 days ago`. כאן הטקסט מפוצל בין צמתים. ב-0.0.1 נתרגם רק את הצמתים הקבועים ("opened this issue"); הצמתים הדינמיים (שם משתמש, תאריך) יישארו כפי שהם. ב-0.1 נוסיף **תבניות שלד** (skeleton): מחברים את הטקסט עם סימון `{0}` לכל אלמנט-ילד, מתרגמים, ומחלקים חזרה.

### 2.6 תכונות (attributes) שמתורגמות
`placeholder`, `aria-label`, `title`, `alt`, `data-disable-with`, `data-confirm`, וגם `value` רק עבור `input[type=submit|button|reset]`.
אותו מילון, אותו אלגוריתם. נצפה ב-`MutationObserver` עם `attributeFilter`.

### 2.7 כותרת הדף (`document.title`)
GitHub מרכיב כותרות כמו `Pull requests · owner/repo`. מפצלים לפי ` · ` ו-` - `, מתרגמים כל קטע בנפרד, ומחברים חזרה. שמות repo לא יימצאו במילון ולכן יישארו.

### 2.8 מנגנון DOM
- **ריצה:** `@run-at document-start` כדי להתחיל לפני שהדף מצויר ולמנוע הבהוב אנגלית.
- **מעבר ראשוני:** `TreeWalker` על `SHOW_TEXT`, עם דילוג על אזורי skip (סעיף 5).
- **שינויים דינמיים:** `MutationObserver` על `document.documentElement` (`childList`, `subtree`, `characterData`). אוספים רק צמתים שנוספו/שונו לתור, ומעבדים בקבוצות (`requestIdleCallback` / `requestAnimationFrame`, תקציב של 12ms לכל סבב (השאר נדחה ל-`setTimeout`)).
- **ניווט בלי רענון:** מאזינים ל-`turbo:render`, `turbo:load`, `soft-nav:end`, `pjax:end` ולוחצים מחדש על מעבר מלא על הדף.
- **Shadow DOM:** סורקים `element.shadowRoot` פתוחים ומחברים להם Observer נפרד.
- **מניעת לולאות:** שומרים `WeakMap<Node, {src, out}>`. אם `node.nodeValue === out` — מדלגים. אם GitHub/React כתב אנגלית חדשה לאותו צומת — מתרגמים שוב.
- **שינוי `nodeValue` בלבד:** לא עוטפים צמתים באלמנטים ולא מחליפים צמתים, כדי לא לשבור Frameworks (React) שמחזיקים הפניה לצומת.
- **תיעוד המקור:** `WeakMap` שומר את הטקסט המקורי (לאיסוף, לדיבוג ולתצוגה "הצג מקור").

### 2.9 תאריכים יחסיים
GitHub משתמש באלמנטים `relative-time` / `time-ago`. נבדוק אם הוספת `lang="he"` גורמת להם להציג עברית דרך `Intl`. **להוכיח בבדיקה** לפני שמתחייבים; אם לא עובד — נעביר ל-0.1.

## 3. המילון

### 3.1 פורמט זמן ריצה (`dict/he.json`, נוצר בבנייה)
```json
{
  "meta": { "lang": "he", "schema": 1, "built": "2026-10-12T08:00:00.000Z", "version": "0.0.1", "count": 3500, "rev": 1 },
  "strings": { "Sign in": "כניסה" },
  "scoped": [
    { "en": "Open", "he": "פתוח", "scope": { "selector": ".State" } }
  ]
}
```
מפתח שמכיל `{n}`/`{1}`… נחשב **תבנית** אוטומטית.

### 3.2 מקורות המילון (`dict/sources/`) — לפי עדיפות
| קובץ | תוכן | סטטוס |
|---|---|---|
| `manual.json` | תרגומים שנכתבו/תוקנו ידנית | גובר על הכול |
| `reviewed.json` | מחרוזות שנאספו ותורגמו ואושרו | מהימן |
| `seed-app.json` | זוגות אנגלית-עברית מהתרגום של אפליקציית האנדרואיד | **לא מאושר** — רק התאמה מדויקת למחרוזת קיימת באתר |

### 3.3 זרע מהאפליקציה
- ייצוא מהעבודה שכבר נעשתה (כ-3,700 מחרוזות + רבים).
- המרת פלייסהולדרים: `%s`→`{1}`, `%1$s`→`{1}`, `%2$s`→`{2}`, `%d`→`{n}`.
- **אין הנחה לגבי החפיפה** עם הממשק של האתר; היא תימדד אחרי הסריקה הראשונה (סעיף 6.8). רשומות זרע משמשות רק כשהאנגלית זהה לחלוטין.

### 3.4 כללי תרגום (קובץ `docs/GLOSSARY.md`)
- נשארים באנגלית: commit, pull request (PR), issue, branch, repository (repo), fork, merge, rebase, squash, review, workflow, release, tag, gist, milestone, label, assignee, discussion, project, Actions, Copilot, Dependabot, Codespaces, README, diff, star/unstar (בפועל "כוכב").
- פנייה: **לשון רבים, ניטרלית** ("לחצו", "בחרו") — כמו באפליקציה.
- שמות פעולה: שם-פעולה ("ביצוע", "יצירת", "הוספת"), לא פועל מצווה, בכפתורים ובתפריטים.
- ללא ניקוד. סימני הפיסוק נשמרים כמו במקור האנגלי.
- שמות מוצרים/תכונות של GitHub — באנגלית כשהם שם עצם פרטי.

### 3.5 בדיקות אוטומטיות על המילון (CI)
- JSON תקין, בלי מפתחות כפולים.
- זהות פלייסהולדרים בין המקור לתרגום (`{n}`, `{1}`…).
- אין ערכים ריקים; אין רווחים בקצה.
- התראה (לא כישלון) אם התרגום ארוך מפי 2.5 מהמקור.
- אין תווי בקרה (U+202A–U+202E, U+2066–U+2069) בערכי המילון — את אלה מוסיף הסקריפט.

### 3.6 עדכון אוטומטי של המילון

**למה:** בהתחלה יהיו עדכוני מילון תכופים; לא רוצים לדרוש מהמשתמשים התקנה מחדש של הסקריפט בכל פעם.

**איך:**
1. ה-CI בונה את המילון בכל מיזוג ל-`main` ומפרסם אותו כ-`he.json` בענף `dist` (שדה `meta.built` עם חותמת זמן; לא משתנה אם התוכן זהה).
2. הסקריפט, ~4 שניות אחרי טעינת הדף ולכל היותר פעם ב-6 שעות, מבקש את `he.json` מהענף `dist` ב-`raw.githubusercontent.com` (גיבוי: `cdn.jsdelivr.net/gh/…@dist/`) באמצעות `GM_xmlhttpRequest` (עוקף את ה-CSP של האתר; דורש `@connect`).
3. אם `meta.built` חדש יותר ממה שהסקריפט משתמש בו — המילון עובר ולידציה ונשמר במטמון (`ghe.dictCache`), ומוחל מיד על הדף הנוכחי.
4. בטעינה הבאה נבחר המילון הטרי יותר מבין המובנה והמטמון.

**הגנות (המילון הוא קלט לא מהימן):**
- סכמה: `meta.schema` גדול מהנתמך → נדחה כולו.
- גודל מרבי 3MB, עד 30,000 רשומות, מפתח עד 300 תווים וערך עד 400.
- כל רשומה נבדקת: placeholders זהים, בלי כתובות/HTML בערך (אלא אם הם גם במקור), בלי תווי בקרה/כיוון, בלי רווחי קצה.
- **רשומה פגומה נזרקת והשאר נשמר** (בזמן ריצה); ב-CI כל רשומה פגומה נכשלת.
- מילון עם פחות מ-50 רשומות נחשב חשוד ונדחה.
- ההחלפה היא של טקסט בלבד (`nodeValue`/`setAttribute`); אין `innerHTML`, אין `eval`.
- אפשר לכבות את העדכון בתפריט.

**סיכון שנשאר:** מי ששולט במאגר שולט בטקסט שמוצג למשתמשים ב-github.com (למשל טקסט מטעה). מומלץ: אימות דו-שלבי לחשבון, הגנת branch על `main` ו-PR לשינויי מילון.

**[לא נבדק מול האתר]** — בדיקה מול `raw.githubusercontent.com` האמיתי; ב-NetFree ייתכן שהוא חסום (ואז נשאר המילון המובנה).

## 4. כיווניות (RTL)

הדרישה: **הטקסט העברי מימין לשמאל, בלי יישור לימין ובלי להפוך את הפריסה.**

### 4.1 למה זה לא טריוויאלי
משפט עברי עם מונחים באנגלית ("ביצוע commit לשינויים") מוצג נכון רק כשכיוון הפסקה הבסיסי הוא RTL. אבל `direction: rtl` על אלמנט שמכיל גם אייקון (SVG) וגם טקסט **הופך את סדר הילדים** ב-Flex ומזיז את האייקון לצד הלא נכון.

### 4.2 הפתרון — מצב `auto` (ברירת מחדל)
| סוג הצומת | טיפול |
|---|---|
| צומת טקסט שהאלמנט-אב שלו הוא **עלה** (אין לו ילדי-אלמנט) | מוסיפים לאב את התכונה `data-ghe` ו-CSS: `[data-ghe]{direction:rtl;unicode-bidi:isolate;text-align:left}` |
| צומת טקסט שיש לאב שלו אחים מסוג אלמנט (אייקון, badge) | עוטפים את הערך במקום ב-DOM: `U+2067` (RLI) + עברית + `U+2069` (PDI) |

תוצאה: הטקסט RTL, האלמנט נשאר במקומו, וכל שאר הדף נשאר LTR. היישור נשאר שמאלי.

### 4.3 מצבים נוספים (הגדרה)
- `css` — רק תכונה + CSS (עלול להזיז אייקונים).
- `isolate` — רק תווי RLI/PDI בכל מקום.
- `off` — בלי טיפול בכיוון.

### 4.4 מגבלות ידועות
- תווי בקרה בטקסט משפיעים על **העתקה**, על **חיפוש בדף (Ctrl+F)** ועל סקריפטים של GitHub שקוראים `textContent` להשוואה. לכן מצב ה-`isolate` מוחל רק בצמתים שאינם עלים.
- `text-overflow: ellipsis` ב-`direction: rtl` חותך מצד שמאל. נבדוק ב-0.0.1 ונתקן אם נתקלים בכך.
- מספרים ותווי פיסוק בקצה המשפט עשויים להתמקם "הפוך"; מטפלים ברשומות בודדות לפי צורך.

## 5. אזורים שאסור לגעת בהם (Skip rules)

### 5.1 אלמנטים
`script`, `style`, `noscript`, `template`, `svg`, `textarea`, `pre`, `code`, `kbd`, `samp`, `[contenteditable]`, `input` (ערך שהמשתמש הקליד), `select option[value]` של משתמשים.

### 5.2 תוכן משתמשים (סלקטורים; יתעדכנו עם הזמן)
- `.markdown-body`, `.comment-body`, `.js-comment-body`

## 6. מנגנון האיסוף (Collector)

### 6.1 מה הוא עושה
כשמצב איסוף פעיל, כל צומת טקסט/תכונה שעובר את בדיקות ה-skip **ולא נמצא לו תרגום** נרשם כמועמד לתרגום.

### 6.2 איפה המילים נשמרות
**מקומית בלבד**, באחסון של Tampermonkey (`ghe.collected`). שום דבר לא נשלח לשום מקום עד שהמשתמש לוחץ "שליחה".

### 6.3 מבנה רשומה
```json
{
  "en": "Create new file", "kind": "text", "seen": 7,
  "pages": ["/:owner/:repo", "/settings/profile"],
  "owners": ["a1b2c3d4"], "repo": true,
  "ctx": "BUTTON.btn", "first": "2026-10-12", "last": "2026-10-12"
}
```
- `kind`: `text` או `attr:placeholder` / `attr:aria-label` וכו'.
- `pages`: **תבניות נתיב**, לא כתובות אמיתיות (`/octocat/Hello-World` → `/:owner/:repo`).
- `owners`: גיבוב FNV של שם ה-owner (לא השם) — רק לספירת "בעלים שונים".
- `ctx`: תג + מחלקה ראשונה של האב. בלי תוכן.

### 6.4 פרטיות — ההגנות
1. **לא אוספים מ-repos פרטיים:** כשאיסוף פעיל, דפי repo פרטי לא נספרים (`meta[name="octolytics-dimension-repository_public"]`). **[לא נבדק מול האתר]**
2. **רק אזורים שאינם skip** (סעיף 5).
3. **סף חזרתיות:** `seen ≥ 3` **ו**-`pages ≥ 2` תבניות נתיב שונות; במחרוזת שנראתה בדפי repo — גם `owners ≥ 2`.
4. **סינון צורה (`sanitize`):** נדחים כתובות/אימיילים, hash, אזכורי `@`, `owner/repo` ונתיבים, טוקנים באותיות קטנות (שמות משתמש/branch), תאריכים מוחלטים, טקסט בעברית, אורך < 2 או > 120. מספרים → `{n}`.
5. **ביקורת אנושית:** לפני כל שליחה מוצגת הרשימה המלאה, עם אפשרות לבטל כל פריט, ו**תיבת אישור** מפורשת.
6. **סינון חוזר בצד המפתח** (`merge_collected`) — לא סומכים על הלקוח.
7. **מחיקה:** פקודת תפריט.

> הסף וה-`sanitize` מצמצמים סיכון ואינם מבטלים אותו. הביקורת האנושית היא ההגנה העיקרית.

### 6.5 הזרימה מקצה לקצה
```
גלישה (איסוף פעיל) → אחסון מקומי (עם סף)
   → 📤 שליחה למפתח → חלון אישור → Issue ציבורי [collected]
   → (CI) מתייג "collected"
   → tools/merge_collected.mjs: איחוד, סינון חוזר, הסרת מה שכבר במילון
   → dict/sources/pending.json (אנגלית בלבד)
   → תרגום → reviewed.json → build (CI) → dict/he.json
   → עדכון אוטומטי אצל המשתמשים
```

### 6.6 תרומה ללא כפתור
ייצוא קובץ JSON, או "העתקה ללוח" והדבקה ב-Issue חדש (תבנית `collected-strings.md`).

### 6.7 דיבוג
`unsafeWindow.GHE`: `stats()`, `untranslated()`, `reload()`, `status()`, `updateNow()`.

### 6.8 כיסוי נמדד
`כיסוי = מתורגם / (מתורגם + לא מתורגם)` לדף הנוכחי. משמש לקריטריוני הקבלה.

### 6.9 שליחה למפתח

**ממשק:** כפתור צף "📤 שליחה למפתח (N)" (מופיע רק כשיש מחרוזות מוכנות ואיסוף פעיל), ופקודה בתפריט. הלחיצה פותחת חלון (Shadow DOM, בלי `innerHTML`) עם:
- הסבר ואזהרה: ה-Issue **ציבורי** ויופיע בחשבון GitHub של המשתמש;
- רשימת המחרוזות עם תיבות סימון ו"בחירת הכול/ביטול בחירה";
- תיבת אישור ("עברתי על הרשימה…") — **הכפתור "שליחה" כבוי עד שמסמנים אותה**;
- כפתורים: שליחה כ-Issue ציבורי · העתקה ללוח · פתיחת Issue ידנית · סגירה.

**למה לא "אוטומטי" ברקע:** כל שליחה יוצרת Issue ציבורי תחת שם המשתמש. לכן ההחלטה היא בכוונה — **שליחה רק בלחיצה ובאישור**.

**מנגנון השליחה (אין טוקן, אין שרת ביניים):**
1. `GET /YSmauas/github-he/issues/new?template=collected-strings.md` עם ה-session של המשתמש (same-origin).
2. מחפשים בדף את הטופס שה-`action` שלו מסתיים ב-`/issues` ויש בו `issue[body]`; אוספים את כל השדות (כולל `authenticity_token`).
3. מציבים `issue[title]` ו-`issue[body]`, ושולחים `POST` (urlencoded) עם `redirect: follow`.
4. הצלחה = כתובת התגובה הסופית היא `/issues/<מספר>`.
5. שגיאות מסווגות: `login`, `form-not-found`, `rate` (429), `rejected` (422), `network`, `unexpected`.

**חלוקה:** גוף Issue מוגבל ל-60,000 תווים; מעבר לכך מפוצל לכמה Issues (עד 5 בהפעלה, השהיה 3.5 שניות ביניהם). מה שנשאר יישלח בהפעלה הבאה.

**אחרי הצלחה:** הרשומות שנשלחו נמחקות מהאיסוף ומסומנות `sent` כדי שלא ייאספו שוב.

**חלופות כשהשליחה נכשלת:**
- "פתיחת Issue ידנית": כתובת עם `title` ו-`body` ממולאים (אם הכתובת ≤ 7,000 תווים), אחרת — העתקה ללוח ופתיחת הטופס;
- "העתקה ללוח".

**צד המפתח:**
- `label-collected.yml` מתייג אוטומטית Issues שכותרתם `[collected]…`;
- `tools/merge_collected.mjs` קורא גופי Issue (בלוק ` ```json `) או קבצי JSON.

**[לא נבדק מול האתר]:** התאמה של שדות הטופס והתנהגות ההפניה של GitHub. בבדיקות הדפדפן נבדקו מול עמוד דמה בלבד.

## 7. קבצי ZIM וחילוץ אופליין (כלי עזר, לא חלק מהסקריפט)

**מה זה עוזר:** קובץ ZIM (פורמט Kiwix) הוא ארכיון של דפי HTML. אפשר להריץ עליו כלי חילוץ שקורא את הדפים, מוציא את צמתי הטקסט לפי אותם כללי skip, ומפיק קובץ `pending.json` בלי לגלוש.

## 10. בנייה והפצה

### 10.1 כלים
Node ≥ 18. חבילת CommonJS קטנה שנכתבה בפרויקט (`tools/build.mjs`) — **בלי תלויות** (ו-Playwright רק לבדיקות e2e).

### 10.2 כותרת הסקריפט
ראו `src/meta.header.txt`. עיקרי הדברים:
```js
// @match        https://github.com/*
// @run-at       document-start
// @noframes
// @grant        GM_getValue / GM_setValue / GM_deleteValue / GM_registerMenuCommand
// @grant        GM_xmlhttpRequest / GM_setClipboard / unsafeWindow
// @connect      raw.githubusercontent.com
// @connect      cdn.jsdelivr.net
// @updateURL    https://raw.githubusercontent.com/YSmauas/github-he/dist/github-he.meta.js
// @downloadURL  https://raw.githubusercontent.com/YSmauas/github-he/dist/github-he.user.js
```
`@connect` נדרש רק לעדכון המילון. שליחת ה-Issue היא same-origin ולא דורשת הרשאה.

### 10.3 פרסום ועדכון קוד
`@updateURL` מצביע על `github-he.meta.js` (כותרת בלבד, קל לבדיקה), ו-`@downloadURL` על הסקריפט המלא. העדכון נעשה על ידי Tampermonkey לפי הגדרות המשתמש.

### 10.4 CI
- `ci.yml` — **`check`** בכל push/PR: ולידציה של המילון, build, בדיקות יחידה (כולל בדיקת התוצר הבנוי);
- **`publish`** — רק אחרי מיזוג ל-`main` ורק אם `check` עבר:
  1. טוענים את הבנייה הקודמת מענף `dist` (כדי ש-`meta.built` לא יזוז כשהמילון זהה);
  2. build;
  3. אם התוצר השתנה: קומיט לענף **`dist`** (קבצים שטוחים: `github-he.user.js`, `github-he.meta.js`, `he.json`, `SHA256SUMS`) — **זה מקור העדכון האוטומטי**;
  4. אם התוצר השתנה: Release מתגלגל `latest-build` (pre-release) עם אותם קבצים;
  5. אם `version` ב-`package.json` חדשה: Release `vX.Y.Z` עם הערות שחרור (pre-release כל עוד 0.0.x).
- **הקבצים הבנויים לא נשמרים ב-`main`** (`dist/` ו-`dict/he.json` ב-`.gitignore`), כך שאפשר להגן על `main` (PR + בדיקות חובה) בלי שה-CI יצטרך לעקוף את ההגנה. הענף `dist` נכתב רק ע"י ה-CI.

### 10.5 נטפרי
- אם `raw.githubusercontent.com` חסום — העדכון האוטומטי נכשל בשקט והסקריפט ממשיך עם המילון המובנה; ההתקנה אפשרית מקובץ.
- לא נדרשת תעודה מיוחדת: הבקשות עוברות דרך הדפדפן.

### 10.6 הבהרה משפטית
הפרויקט **אינו קשור ל-GitHub** ואינו מאושר על ידה. הטקסטים האנגליים הם מפתחות בלבד.
