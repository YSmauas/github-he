# מילון מונחים וכללי תרגום

## מונחים שנשארים באנגלית
commit, pull request (PR), issue, branch, repository (repo), fork, merge, rebase, squash, review, reviewer, workflow, job, release, tag, gist, milestone, label, assignee, discussion, project, Actions, Copilot, Dependabot, Codespaces, README, diff, draft, checks, artifact, webhook, secret, sponsor.

## כללים
1. **פנייה:** לשון רבים ניטרלית ("לחצו", "בחרו", "הוסיפו"). לא "אתה/את".
2. **כפתורים ותפריטים:** שם פעולה ("ביצוע", "יצירת", "הוספת", "מחיקת"), לא פועל ציווי.
3. **סדר מילים:** מונח באנגלית בתוך משפט עברי — כותבים כמו שמדברים: "ביצוע commit לשינויים", "פתיחה מחדש של issue".
4. **ניקוד:** בלי.
5. **פיסוק:** נשאר כמו במקור (`…` נשאר `…`, נקודתיים נשארות).
6. **placeholders:** `{n}` (מספר), `{1}`, `{2}` (טקסט) — חייבים להופיע בתרגום בדיוק כמו במקור, בכל סדר.
7. **יחיד/רבים:** רשומה נפרדת למקרה היחיד (`1 commit`) — היא גוברת על התבנית (`{n} commits`).
8. **שמות מוצרים ותכונות של GitHub:** באנגלית כשהם שם פרטי.
9. **אין** כתובות URL או HTML בתרגום (CI ידחה).
10. **אין** תווי כיוון (RLI/PDI/LRM/RLM) בתרגום — הסקריפט מוסיף אותם בעצמו.

## זהירות: מילים עם כמה משמעויות
`Open` (פתוח / לפתוח), `Close` (סגירה / סגור), `Star` (כוכב / לסמן בכוכב), `Watch`. אם נדרש הקשר, משתמשים ב-`scoped` (ראו SPEC).
